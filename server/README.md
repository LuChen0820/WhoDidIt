# 谁在干活 · 后端

小组作业贡献结算台的真实后端。**不是原型**：数据落在真 Postgres 里，结算值由事件流算出来。

```bash
npm install
npm test              # 39 条不变量测试（内存库，不落盘）
bash scripts/smoke.sh # 41 项端到端冒烟：起真服务、走真 HTTP、带真 cookie
npm run e2e             # 10 项 Playwright 浏览器测试（真 Chromium，覆盖 DOM 层）
npm run demo          # 打印一份完整场景的结算单
npm run probe         # 攻击面自检：确认已封堵的洞没被重新打开
PORT=8790 node src/server.ts   # 启动，浏览器打开 http://127.0.0.1:8790
```

## 这里跑的是真 Postgres

开发期用 [PGlite](https://pglite.dev)（Postgres 编译成 WASM，跑在 Node 进程里），**零安装、不需要 Docker**，但 SQL、触发器、`jsonb`、生成列全是真的。
上生产时把 `src/db.ts` 的 `open()` 换成 `pg` 连接池即可，**迁移脚本和派生 SQL 一行都不用改**。

## 五条不可违反的规则

每条都有对应的测试，改坏了 CI 就红。

| 规则 | 为什么 | 测在哪 |
|---|---|---|
| `events` 只追加，不可 UPDATE / DELETE / TRUNCATE | 结算单必须能事后自证没被改过 | `ledger.test.ts` 第 1 条 |
| `server_time` 由数据库生成 | 客户端时间不可信，否则能伪造加班 | 第 2 条 |
| `actor_id` 只来自 session，请求体里的 `actorId` 一律不读 | 若客户端能自称他人，整套痕迹一文不值 | `http.test.ts`「请求体里塞 actorId 无效」 |
| 验收人 ≠ 负责人，且同一任务只有第一次验收计分 | 杜绝自验自计和重复验收造分 | 两处 |
| 只有叶子任务计分；验收奖不计入总分 | 拆包不能凭空造分；组长不能靠验收权给自己加分 | 两处 |
| 一个任务只有一条逾期事实，且未到期不能按逾期关闭 | 逾期分不能靠重复记录或提前关闭来操纵 | `ledger.test.ts`「逾期」5 条 |

## 结算值怎么来的

```
points = 交付分（被他人验收的叶子任务权重之和）
       + 出勤分（签到 +0.5 / 缺席 −1.5）
       + 逾期分（迟交 −0.5 × 自然日数，单任务封顶 7 天）
       + 仲裁调整（dispute_decided 事件带来的转移）

占比 = points / 全组正分之和 × 100      非正分不显示占比，显示「—」
```

**逾期是事件，不是查询结果。** 如果每次读看板时用 `today > due_date` 现算，那么一个人迟交 3 天后终于交付，他的历史就会随「你什么时候问」而改变——账本不再可重放。所以迟交天数只在任务终结的那一刻（被验收、或被组长按逾期关闭）写进 `events`，并用部分唯一索引保证一个任务只有一条逾期事实。看板上那个红色「逾期 N 天」是纯展示，不参与计分。

**非正分不显示占比。** 「占比 −9.3%」不是占比，是负数除正数的副产品；这个人拖后腿的信息已经在红色扣分条和 `逾期 −3.5` 标签里说清楚了，不需要靠一个假数字表达。

`ledger` 是**纯派生表**。任何时候 `delete from ledger` 再重算，结果必须逐字节一致——这条被测试钉死了。
所以「这个数字怎么来的」永远有答案：把 `events` 按 `seq` 重放一遍即可。

### 两个后来才想清楚的规则

**验收奖不计入总分。** 第一版把「验收他人产出」按 0.5 分计进总分，跑真实场景才发现：组长一个人做了 7 次验收，3.5 分占到他总分的 37%。也就是**谁掌握验收权，谁就在给自己打分**，这和「不互评是为了避免人情分」的初衷直接冲突。现在验收动作仍然被完整记录和展示，但不参与排名。

**占比的分母是「正分之和」，不是「全员之和」。** 仲裁会把误记的分数转走，可能让某人变成 0 分甚至负分；若用全员总和当分母，正负一抵消就可能得到 0 或负数，占比直接失真。

## 身份设计：没有密码

无 HTTPS 的环境下传密码等于明文裸奔，所以干脆不设密码：

- 组长建组 → 生成一次性邀请链接（内含随机 token，7 天过期，用过即废）
- 组员打开链接，填**姓名 + 学号后四位**，两者必须与邀请记录一致才放行
- 换发一个 90 天的 HttpOnly cookie，库里只存 token 的 sha256

「姓名 + 学号后四位」是组长与组员之间本来就共享的凭证。这比密码更贴合场景，也顺手满足了「身份必须绑定到人」这条要求。

## 前端：`web/`，零构建

三个文件：`index.html` + `app.css` + `app.js`（ES module，无打包、无框架、无构建步骤），由 Fastify 直接托管。

**这里偏离了 `tech-design.md` 里写的 Vue 3 + Vite，是有意的**：当时的目标是"这周就能用它开一次周会"，引入构建链会多出一整天不产生可用性的工作。代价是 `app.js` 里的字符串模板拼装会在页面变多之后开始难维护——真要长期做，仍然应该迁到 Vue，视觉和接口都能平移。

三个视图：**任务看板**（占比条 + 四态任务）、**贡献结算单**（构成明细 + 事件指纹 + 导出 + 组长仲裁）、**组员与邀请**（成员表 + 签到缺席 + 一次性邀请链接）。任务详情走抽屉，承载证据链和全部动作按钮。

安全上有一条硬要求：**所有用户输入（姓名、任务标题、链接）插入 DOM 前必须过 `esc()`**。任务标题是别人写的内容，不过转义就是存储型 XSS。

## 响应快慢：先量，再改

有反馈说"有的点了很快，有的很慢"。测下来**数据库不是原因**（`npm run bench`，605 条事件）：

| | 165 事件 | 605 事件 |
|---|---|---|
| `computeLedger` 重算账本 | 5.6ms | 7.9ms |
| `eventsHash` 全表指纹 | 3.5ms | 13.1ms |
| 一次完整写操作 | 11.1ms | 13.2ms |

我原本怀疑账本里那个 `not exists` 去重子查询是 O(n²)，实测不成立——Postgres 用的是哈希反连接。`eventsHash` 线性增长，但一学期量级也就 40ms，不值得为它做增量。

**真正的慢感来自"点了没有任何反馈"**：切 tab、开关抽屉是纯本地渲染所以瞬间响应；而认领/提交/验收要走 4–5 次串行 HTTP 往返，期间按钮不变灰、不转圈、文案不改。一百多毫秒的零反馈，人会判断成"没点上"，于是再点一次——然后收到一个错误 toast。

三处改动：
1. **点击即反馈**。`guard(fn, el)` 立刻把按钮置为 `处理中…` 并 `disabled`，失败才恢复。实测点击 200ms 后按钮已是禁用态。
2. **看板一次返回结算数据**。`/api/board` 直接带上 `ledger`，省掉一次 `/api/ledger` 往返。
3. **抽屉先渲染再补数据**。标题、负责人、动作按钮全部用手上已有的数据同步画出来，证据链留占位、异步补；并用 `drawerTaskId` 丢弃过期响应，避免用户快速切换任务时看到串台的内容。

顺带去掉了一个反直觉行为：验收成功后原本会自动跳到结算单页，现在留在看板并弹出「已验收 · 林嘉 现为 39.8%」——占比条就在眼前变了，比跳页更有说服力。

## 攻击面：`npm run probe`

`scripts/probe.ts` 不是演示脚本，是**攻击自检**。每次改动后跑一遍，确认已经堵住的洞没被重新打开。

```
✓ 已知攻击面全部已封堵
```

它盯的是同一个原则：**每一个能加分的动作，都必须绑定一个具体的、不可重复的对象。**
缺了这条，机制再对也能被刷穿。已经因此修掉三个洞：

| 洞 | 症状 | 封堵方式 |
|---|---|---|
| 签到可连点刷分 | 组长点 20 次「签到」→ 一个人占比 100% | 新增 `meetings` 表；出勤必须挂会议，`events` 加 `meeting_id`/`subject_id`，**部分唯一索引**保证一人一会只有一条出勤事实；并有 CHECK 约束让不挂会议的出勤根本写不进来 |
| 组员可自建高分任务 | 林嘉给自己建 20 分任务 → 占比 100% | `createTask` 改为组长专属。派活要组长权限而定价不要，等于把定价权发给想省钱的人 |
| 证据链链接是存储型 XSS | 提交 `javascript:alert(document.cookie)` 会被渲染成可点链接 | `safeUrl()` 只放行 http/https，服务端拒绝 + 前端 `safeHref()` 双保险。`esc()` 只转义引号，**挡不住协议级攻击** |

改错账不走"再点一次"，只能走仲裁（`dispute_decided`）——这样任何对已记账号的修改都留下一条可审计记录。

## E2E：`npm run e2e`

10 项 Playwright 测试，跑真 Chromium、真点击。**它不是装饰——上线前它抓出两个 39 条单元测试 + 41 项 HTTP 冒烟全绿时依然存在的真 bug：**

| bug | 为什么前面的测试抓不到 |
|---|---|
| **多租户串数据**：`computeLedger(groupId)` 的重建 SQL 漏了 `group_id` 过滤，会往账本里插入**全库所有组**的成员。第二个组一打开看板就主键冲突 500 | 单元测试每个用例都只建一个组；冒烟测试的"组间隔离"只打了任务接口，从没调用过第二个组的 `/api/board` |
| **遮罩层泄漏**：`accept` / `decline` / `split` / 逾期关闭 四个处理器只关抽屉不关遮罩，用户验收完一次之后**整个页面再也点不动** | 纯 DOM 层问题，HTTP 层根本不存在这个概念 |

第一条尤其能说明问题：那是一个会让产品「第二个用户一用就崩」的缺陷，而当时我完全以为它是好的。

写这些测试的过程中我自己也犯了同类错误：把 `hideDrawer()` 的批量替换跑在了它自己的函数定义上，变成 `function hideDrawer(){ hideDrawer() }` —— 无限递归。**批量文本替换必须排除定义处。**

覆盖范围：首屏无未捕获异常、建组与身份显示、三个 tab 可切换、新建任务入列、跨用户派活提交验收与占比重算、验收后遮罩关闭、负责人看不到验收按钮、驳回退回重做只计一次分、`javascript:` 链接被拒、负分成员显示「—」。

## 已知边界

- **单进程单连接**：PGlite 不支持并发写。20 人规模的课程项目够用，上生产换连接池。
- **无 HTTPS**：当前只能 IP + HTTP，正式给同学用之前必须补上（见 `../tech-design.md` §1 的备案说明）。
- **权重由组长定**：这是有意的，但意味着组长仍是权力中心，所以权重变更和裁决全部进事件流，可申诉。
- **测试没有接 CI**。四层检查都得靠人记得跑。下一步加 GitHub Actions，否则它们迟早变成摆设。
- **没有视觉回归**。E2E 验证的是结构和行为，不是像素；配色、间距、响应式断点仍要靠人眼。
- 课程作业用的假数据原型在仓库根的 `../index.html`，与这里的真应用无关，保留作演示交付物。

## 开发过程中被测试抓到的四个 bug

留在这里，因为它们各自代表一类会反复犯的错：

1. **表单留空的日期让服务端 500**。`dueDate ?? null` 挡不住空字符串——空串不是 null，Postgres 插 `date` 直接报错。边界输入必须在服务端归一化，不能指望前端。
2. **导航按钮点了没反应**。`index.html` 里的三个 tab 只有 `data-v`、漏了 `data-act`，事件委托根本匹配不上。HTTP 冒烟测试全绿也测不出来，因为它不点 DOM。
3. **`3.40 分` 和 `3.4 分` 混着显示**。`numeric(6,2)` 返回补零字符串，而事件 payload 里存的是 JS number。已在查询侧 `::float8`、写入侧 `Number()` 统一。
4. **占比分母用全员总和**。仲裁会把误记的分转走，一旦有人归零或变负，正负抵消后分母可能为 0 甚至负数。改为以「正分之和」为分母。
